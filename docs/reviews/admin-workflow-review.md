# MedKothay: admin workflow review

**Reviewed:** 19 November 2026. **Basis:** local `main` checkout `9771d92`, the four requested project documents, relevant admin and registration screens, the live demo at https://med-kothay.vercel.app, and DGDA primary sources. **Scope:** product/workflow only. No app code was changed.

**Evidence convention:** `file:line` identifies a local observation; **Live** identifies a screen I viewed with the provided sample admin account; **Inference** identifies a consequence of the planned model, rather than a measured production failure. B1/W1 have not been built (`docs/STATUS.md:26-39`). Mock success with unchanged lists and the licence-photo placeholder are disclosed by the UI (`review-actions.jsx:28-51`, `catalog-manager.jsx:21-30`, `admin/pharmacies/[id]/page.js:78-87`); they are expected phase limitations, not bugs.

**Effort:** S = under 1 hour; M = about half a day; L = a day or more. “Demo” means the three-day staged build; “launch” means real pharmacies/customers.

### Bangladesh / DGDA fit

**Human verification, not an official integration:** DGDA **Form 7** asks whether the licence covers retail or wholesale, the premises, and pharmacist supervision. DGDA's model pharmacy/medicine shop guideline checks a valid licence for the premises and a current Pharmacy Council of Bangladesh (PCB) registration for a dispensing professional; its checklist records shop address, licence and PCB numbers and their validity. DGDA's document list for *new model retail outlets* includes a current trade licence and premises evidence. The precise requirements for every ordinary retail outlet and a public real-time licence-check endpoint were **not verified** here. Sources: [DGDA Form 7](https://dgda.gov.bd/sites/default/files/files/dgda.portal.gov.bd/page/393e45f2_a695_4b5d_8d53_79bcbe82b88a/2023-10-11-05-24-564d3c1af2b08debf5fdc590ca6bd66e.pdf), [DGDA model outlet guideline](https://dgda.gov.bd/sites/default/files/files/dgda.portal.gov.bd/policies/538854fb_87f2_4ecd_97a3_22f1f67a6721/2024-11-28-10-09-f124b507dc7aa84fed18c304ade5c3c3.pdf), [DGDA required document list](https://dgda.gov.bd/sites/default/files/files/dgda.portal.gov.bd/forms/55b66059_6350_4b9e_9352_c067d01275f3/2023-02-14-05-14-09afe3c7bffc1996ca973483c2c8ce5e.pdf).

If an automatic status-changing expiry job is eventually wanted, that explicitly **reconsiders** the “Do NOT build” rule and remains **LATER**, after a renewal/appeal policy exists.

## 4. Overall verdict

**No, not as written for a real database-backed admin journey.** The mock UI is adequate to demonstrate the intended review. Before B1, decide the **resubmission transition**, **expired/duplicate licence policy**, **emergency visibility rule**, and **catalog edit semantics**; add minimal review metadata in the migration, then wire W1. A three-day staged demo can rely on a small manual checklist and an honest limited verification claim while the wider operational console waits.
